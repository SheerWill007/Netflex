# Contributing to Netflex

Thank you for your interest in contributing! This document provides guidelines for contributing to this project.

## 🚀 Getting Started

1. Fork the repository
2. Clone your fork: `git clone <your-fork-url>`
3. Create a feature branch: `git checkout -b feature/amazing-feature`
4. Make your changes
5. Test your changes
6. Commit: `git commit -m 'Add some amazing feature'`
7. Push: `git push origin feature/amazing-feature`
8. Open a Pull Request

## 📝 Code Style

### TypeScript
- Use TypeScript for all new code
- Define proper types and interfaces
- Avoid using `any` type
- Use meaningful variable and function names

### React/Next.js
- Use functional components with hooks
- Use `'use client'` directive for client components
- Keep components small and focused
- Add proper TypeScript types for props

### CSS
- Use CSS custom properties (variables)
- Keep styles scoped to components
- Ensure responsive design

### API/Backend
- Follow RESTful conventions
- Add proper error handling
- Use controllers for business logic
- Keep routes clean and simple

## 🧪 Testing

Before submitting a PR:
1. Test your changes locally
2. Ensure the app builds: `npm run build`
3. Check for TypeScript errors
4. Test on different screen sizes

## 📋 Pull Request Process

1. Update README.md if needed
2. Update documentation if changing functionality
3. The PR will be merged once approved

## 🐛 Reporting Bugs

Include:
- Clear description
- Steps to reproduce
- Expected behavior
- Actual behavior
- Screenshots if applicable
- Your environment (OS, Node version)

## 💡 Feature Requests

Provide:
- Clear description
- Use case and benefits
- Possible implementation approach
